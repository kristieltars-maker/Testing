# UX/UI-дизайн подсистемы «Транскрибация звонков» (transcribe)

> **Статус:** новый документ (подсистемы ранее не было). Спроектирован ДО
> реализации.
> **Назначение:** текстовая спецификация интерфейса одной статической
> страницы `static/index.html` (без сборки, inline CSS/JS, без CDN),
> контейнера `transcribe-app`, поддомен `transcribe.bot-atelier.ru`.
> **Связанные документы:** `.opencode/architecture/transcribe.md`
> (подтверждённая архитектура), `.opencode/design/portal-ui.md`
> (портал, паттерн «На главную», дизайн-токены), `AGENTS.md` §1.1 (SSO),
> §3 (прецедент standalone-подсистемы correction-audio).
> **Язык документа:** русский. **Формат:** только текстовые описания и
> вайрфреймы. Без CSS/JSX/кода.
>
> **Аудитория и роли.** Любой активный пользователь экосистемы, прошедший
> SSO-шлюз nginx. Роль не влияет на интерфейс и **не показывается**:
> шлюз не передаёт идентичность внутрь приложения, поэтому в UI нет имени,
> роли и кнопки выхода. Единственный «выход» — анкер «← На главную».
> Сценарий одиночный и эфемерный: добавить → дождаться → скачать Excel →
> уйти.

## 1. Резюме UX-решений

| Вопрос | Решение |
|---|---|
| Один экран или несколько? | Одна страница-«рабочий стол» без роутинга: шапка, две карточки ввода, общая таблица «Пачка», тосты. |
| Как показать, что режимы можно смешивать? | Две карточки ввода стоят рядом в одной зоне и «льют» в одну общую таблицу; копия заглушки и вводной строки явно разрешает смешивание; Excel один на всю пачку. |
| Загрузка с диска: кнопка или drag&drop? | Оба: drop-зона (пунктирная, вся кликабельна) + кнопка «Выбрать файлы» как очевидный fallback. |
| Файлы уходят по одному (API = 1 файл/запрос) — что видит пользователь? | Локальная «очередь загрузки» под drop-зоной: «Ожидает загрузки» → «Загружается…» → переезд в таблицу; ошибки остаются в очереди с кнопкой «Повторить». |
| Кнопка Excel до готовности пачки: скрыта / неактивна / активна? | **Видима, но неактивна** при непустой пачке, с счётчиком «Обработано X из Y» рядом. Активируется автоматически при `all_terminal`. Появление «из ниотуда» и скачок макета отвергнуты. |
| Частичные ошибки пачки? | Не блокируют Excel; причина ошибки видна в строке таблицы и попадает в колонку «Текст транскрибации» Excel (сообщается подсказкой у кнопки). |
| Что видит пользователь при смерти refreshToken Twin24? | Панель Twin24 возвращается в состояние «не подключён» (форма входа) + спокойная строка: «Добавленные файлы и результаты не потеряны». |
| Построчная валидация Twin24? | По кнопке «Добавить в обработку»: сервер — единственный источник истины; сводка «Принято N / Отклонено M» с причиной по каждой отклонённой строке; принятые строки покидают textarea, отклонённые остаются на правку. |
| Как сообщать про TTL 24 ч и удаление WAV? | Три тихих места: вводная строка под шапкой, примечание у кнопки Excel после первой выдачи, карточка на портале. Без модальных окон и «страшилок». |
| Дизайн-язык? | Гибрид: тёмная шапка MVP (сигнатура standalone-подсистемы) + светлое тело в токенах портала/testing. Подробно — §4. |

## 2. Общая структура страницы

Единая страница, вертикальный поток. Сверху вниз:

1. **Шапка (тёмная, #13213a)** — паттерн шапки MVP acoustic-matcher:
   слева анкер «← На главную», рядом бренд подсистемы (иконка + название
   + подзаголовок). Справа — ничего (нет пользователя, нет выхода).
2. **Вводная строка** (светлое тело, 1–2 предложения) — что делает
   подсистема + честное примечание про срок жизни данных.
3. **Зона ввода** — сетка из двух равнозначных карточек:
   «Файлы с диска» и «Импорт из Twin24». Обе всегда видимы и доступны;
   смешивание разрешено и поддерживается визуально (две двери в одну
   комнату).
4. **Карточка «Пачка»** — полноширинная таблица всех файлов обоих
   источников + счётчики + кнопка «Скачать результат (Excel)». Это
   смысловой центр страницы: зоны ввода на неё «работают».
5. **Тост-зона** — фиксировано внизу справа (паттерн MVP).

```
┌────────────────────────────────────────────────────────────────────┐
│ ШАПКА (тёмная #13213a, sticky)                                     │
│ [← На главную]  [icon] Транскрибация звонков                       │
│                 Записи диалогов — в текст с ролями оператор/клиент  │
├────────────────────────────────────────────────────────────────────┤
│ Вводная строка: назначение + срок хранения данных (muted)          │
│                                                                    │
│ ЗОНА ВВОДА (grid, 2 карточки)                                      │
│ ┌ Карточка А «Файлы с диска» ────┐ ┌ Карточка Б «Импорт Twin24» ──┐│
│ │ подсказка лимитов              │ │ статус подключения          ││
│ │ ┌ drop-зона (пунктир) ───────┐ │ │ форма входа / textarea      ││
│ │ │ [icon] Перетащите WAV…    │ │ │ сводка валидации строк      ││
│ │ │ [ Выбрать файлы ]         │ │ │                              ││
│ │ └───────────────────────────┘ │ │                              ││
│ │ очередь загрузки (временно)    │ │                              ││
│ └────────────────────────────────┘ └──────────────────────────────┘│
│                                                                    │
│ ┌ КАРТОЧКА «ПАЧКА» ─────────────────────────── [Скачать Excel] ──┐│
│ │ счётчики · «Обработано X из Y» · прогресс-полоса                ││
│ │ ─────────────────────────────────────────────────────────────── ││
│ │ Диалог            │ Источник │ Статус            │ Примечание   ││
│ │ zvonok_0901       │ С диска  │ ● Транскрибируется│ —            ││
│ │ 01a0b657-…        │ Twin24   │ ● Готово          │ —            ││
│ │ …                 │          │                   │              ││
│ └──────────────────────────────────────────────────────────────────┘│
│                                                     [тосты: ↘]      │
└────────────────────────────────────────────────────────────────────┘
```

**Адаптив.** ≥900 px — две колонки ввода. <900 px — карточки ввода в
одну колонку (grid `auto-fill` сворачивается, как на портале). Таблица
на узких экранах не превращается в карточки: карточка «Пачка» получает
горизонтальную прокрутку (проще и честнее для no-build страницы).
Шапка — в одну строку; «← На главную» никогда не скрывается.

**Первый рендер.** Статика рисуется мгновенно; параллельно идёт
`GET /api/state`. Пока он не вернулся, в карточке «Пачка» — muted-строка
«Загружаем рабочий стол…». После ответа — либо заглушка (пусто), либо
таблица (см. 3.1, 3.5).

## 3. Экраны и состояния

### 3.1. (а) Стартовое состояние: пустой рабочий стол

**Назначение.** Первый визит (или возврат к очищенному столу). Задача
экрана: за 5 секунд объяснить, что здесь делают, и показать оба пути
ввода как равнозначные.

**Раскладка.** Шапка → вводная строка → две карточки ввода (обе в
«пустом» состоянии: drop-зона без очереди; панель Twin24 в состоянии
«не подключён») → карточка «Пачка» с заглушкой вместо таблицы:

```
┌ КАРТОЧКА «ПАЧКА» ────────────────────────────────────────────────┐
│                        [SVG-иконка списка]                         │
│              Здесь появятся добавленные диалоги                    │
│   Можно смешивать файлы с диска и записи из Twin24 —              │
│   результатом будет один Excel на всю пачку.                       │
└────────────────────────────────────────────────────────────────────┘
```

Заглушка переиспользует паттерн `.empty` портала/testing (центрирование,
`padding 48px 16px`, muted-текст) — никаких новых паттернов.

**Интерактивные элементы и состояния.** Обе панели доступны сразу.
Кнопка «Скачать результат (Excel)» **не отображается** (нет файлов — нет
результата). Никаких блокировок по роли (ролей нет). Лимиты упомянуты
подсказкой в карточке А («WAV · до 25 МБ на файл…») — пользователь знает
правила до первой ошибки.

**Согласованность.** Вводная строка = hero-подзаголовок портала (2
предложения, muted). Заглушка = `.empty`. Карточки = `.card` портала.

**Edge cases.**
- Возврат в **непустой** стол (восстановление по cookie `transcribe_ws`)
  — это состояние не показывается: таблица отрисовывается сразу из
  `/api/state` (см. 3.5).
- Стол, очищенный по TTL, выглядит **так же нейтрально**: сервер не
  сообщает факт очистки, поэтому никаких «ваши данные удалены» —
  честность обеспечивается вводной строкой (3.6) и карточкой портала.
- Cookie потерян (другой браузер, чистка cookies) — тот же нейтральный
  пустой стол; прежние файлы недостижимы, это норма эфемерных столов.

### 3.2. (б) Панель А «Файлы с диска»

**Назначение.** Быстрый путь для тех, у кого WAV уже лежит на диске.

**Раскладка.** Карточка: заголовок «Файлы с диска» + строка лимитов;
drop-зона; очередь загрузки (появляется только когда есть файлы в
полёте или ошибки); после долёта очередь сворачивается.

```
┌ Файлы с диска ──────────────────────────────────────┐
│ WAV · до 25 МБ на файл · до 50 файлов на стол        │
│ ┌────────────────────────────────────────────────┐ │
│ │         [SVG: стрелка вверх в лоток]            │ │
│ │   Перетащите WAV-файлы сюда                      │ │
│ │   или выберите на диске                          │ │
│ │              [ Выбрать файлы ]                   │ │
│ └────────────────────────────────────────────────┘ │
│ Очередь загрузки (только во время загрузки):        │
│  ↻ zvonok_0901.wav    Загружается…                  │
│  · zvonok_0902.wav    Ожидает загрузки              │
│  ✕ zvonok_09.wav      Файл больше 25 МБ  [Повторить]│
│  ✕ final_mix.mp3      Можно загружать только WAV    │
└──────────────────────────────────────────────────────┘
```

**Интерактивные элементы и их состояния.**
- **Drop-зона.** Пунктирная рамка `--border`, внутри SVG-иконка
  (inline, stroke currentColor, viewBox 24), текст и secondary-кнопка
  «Выбрать файлы». Вся зона кликабельна (клик = нативный выбор файлов,
  `accept=".wav"`, `multiple`); зона принимает и перетаскивание.
  Состояния: покой → hover (рамка акцентируется) → **drag-over**
  (фон `--accent-soft`, рамка `--accent`, текст «Отпустите, чтобы
  добавить»).
- **Очередь загрузки.** API принимает один файл за запрос, UI шлёт
  последовательно и показывает честный конвейер. Состояния пункта:
  «Ожидает загрузки» (muted) → «Загружается…» (спиннер) → успех: пункт
  исчезает из очереди и появляется строкой в «Пачке» со статусом
  «В очереди»; ошибка: пункт остаётся красным с причиной и ссылкой
  «Повторить» (повтор ставит его в конец очереди).
- Зона остаётся активной во время загрузки — можно «доливать» до
  лимитов; новые файлы встают в конец очереди.
- **Клиентская валидация до отправки** (мгновенная обратная связь,
  сервер всё равно перепроверяет): не `.wav` → в очередь сразу с
  ошибкой «Можно загружать только WAV»; размер > 25 МБ → «Файл больше
  25 МБ»; имя (без расширения) уже есть в пачке → «Файл с таким именем
  уже в пачке»; файлов в пачке уже 50 → «В пачке уже 50 файлов —
  скачайте результат или начните новый рабочий стол» (см. открытый
  вопрос §5.6); суммарный объём ≥ 1 ГБ → «Превышен общий объём
  рабочего стола (1 ГБ)».
- **Смешанная выборка** (часть файлов валидна, часть нет): валидные
  уходят в очередь, невалидные перечисляются с причинами. Ошибки не
  блокируют валидные — симметрия с панелью Б.

**Согласованность.** Карточка = `.card`; кнопки = `.btn-secondary`
(выбор) и локальная очередь в стиле muted-строк; drag&drop-зона — новый,
но минимальный элемент: пунктир — общепонятная конвенция, цвет —
существующие токены. Иконки — inline SVG, без эмодзи.

**Edge cases.**
- Сбой сети в момент загрузки: пункт красный «Не удалось загрузить
  файл — проверьте связь» + «Повторить». Остальная очередь не
  останавливается.
- Пользователь закрыл вкладку в середине очереди: долетевшие файлы
  уже в пачке и обрабатываются; недолетевшие просто не добавлены
  (никаких «возобновлений» — это рабочий стол, не менеджер загрузок).
- Два файла с одинаковым именем из разных папок: первый принимается,
  второй — «Файл с таким именем уже в пачке» (имя без расширения = ID
  в Excel, дубликаты недопустимы).

### 3.3. (в) Панель Б «Импорт из Twin24»

**Назначение.** Путь для диалогов, уже лежащих в Личном кабинете Twin24.

**Раскладка.** Карточка: заголовок «Импорт из Twin24», статус-строка
подключения, тело состояния. Четыре состояния панели:

**Состояние 1 — «не подключён» (старт):**

```
┌ Импорт из Twin24 ────────────────────────────────────┐
│ ○ Twin24 не подключён                                 │
│                                                       │
│ Email      [___________________________]               │
│ Пароль     [___________________________]               │
│                                                       │
│ [ Подключить ЛК Twin24 ]                              │
│                                                       │
│ Пароль не сохраняется: он нужен один раз, чтобы        │
│ получить токен доступа.                               │
└───────────────────────────────────────────────────────┘
```

- Поля: «Email» (тип email) и «Пароль» (тип password), label над полем —
  паттерн форм testing. Кнопка primary «Подключить ЛК Twin24»; в полёте —
  «Подключаем…» (disabled, спиннер). Обе ошибки показываются инлайн
  красным под формой (не тостами): «Неверный email или пароль Twin24.» /
  «Twin24 недоступен — попробуйте позже.»
- Подсказка про пароль — честная и заметная, снижает страх «отдать
  пароль». Авто-refresh токена происходит на сервере и **невидим** для
  пользователя.

**Состояние 2 — «подключён»:**

```
┌ Импорт из Twin24 ────────────────────────────────────┐
│ ● ЛК Twin24 подключён · user@company.ru               │
│                                        [Сменить учёт- │
│                                         ную запись]   │
│ Диалоги — по одной записи на строку (UUID или ссылка   │
│ на запись в ЛК):                                      │
│ ┌─────────────────────────────────────────────────┐   │
│ │ 01a0b657-6b6b-77ed-b8f9-b41d02cb0b3d            │   │
│ │ https://twin24.ai/app/download/records/01a0b…/  │   │
│ │                                                 │   │
│ └─────────────────────────────────────────────────┘   │
│ [ Добавить в обработку ]                               │
│                                                       │
│ Принято: 5                                            │
│ Отклонено: 2                                           │
│  · строка 3: «twin24.ru/запись» — не похоже на UUID   │
│    или ссылку Twin24                                   │
│  · строка 7: «01a0b657-…» — дубликат: диалог уже      │
│    в пачке                                             │
└───────────────────────────────────────────────────────┘
```

- Статус: зелёная точка + «ЛК Twin24 подключён» (+ email ЛК —
  рекомендую показывать, см. §5.4). Кнопка «Сменить учётную запись» —
  тихая, secondary, мелкая: возвращает форму входа (пароль всегда
  пустое; email подставляется, если сервер держит его в RAM — деталь
  для architect).
- Textarea с примером формата в placeholder. Пустая textarea — кнопка
  «Добавить в обработку» неактивна; в полёте — «Добавляем…» (disabled,
  защита от двойного клика).
- **Валидация — по кнопке, сервер — единственный источник истины**
  (клиент проверяет только непустоту). Ответ `{accepted, rejected}`
  превращается в сводку: принятые строки покидают textarea и
  появляются в «Пачке» со статусом «В очереди»; отклонённые остаются в
  textarea для правки, а в сводке — по одной строке на отклонённое:
  усечённая цитата строки + причина («Не похоже на UUID или ссылку
  Twin24», «Дубликат: диалог уже в пачке», «Диалог не найден в вашей
  ЛК Twin24», «Превышен лимит — 50 файлов на стол»). Пустые строки и
  хвостовые пробелы прощаются молча.
- Если после клика все строки приняты: сводка «Принято: N», textarea
  пустая. Ссылка и «голый» UUID одного и того же диалога распознаются
  как один диалог — второй добавленный вариант отклоняется как
  дубликат.

**Состояние 3 — «сессия истекла / подключение сброшено» (смерть
refreshToken или рестарт контейнера):** визуально то же, что
«не подключён» (форма входа), но с одной поясняющей muted-строкой под
статусом: «Подключение сброшено (истёк доступ или сервер
перезапускался). Добавленные файлы и результаты не потеряны — войдите
заново, чтобы добавить новые диалоги.» Токены Twin24 живут только в
RAM — это честное отражение архитектуры: переподключение нужно **только
для новых импортов**, уже скачанные файлы и результаты не теряются.
Отдельной красной «тревоги» не делаем — состояние рабочее, не аварийное.

**Согласованность.** Формы — паттерн testing (label над полем, ошибка
красным под полем); сводка валидации — паттерн «список ошибок»
портальных форм; статус-точка — существующий pill-бейдж MVP (мягкий
фон, тёмный текст того же оттенка).

**Edge cases.**
- Ошибка сети при «Добавить в обработку»: тост «Не удалось отправить
  строки — попробуйте ещё раз», textarea не очищается, ничего не
  теряется.
- Большая вставка (сотни строк): лишние за пределами лимита отклоняются
  с причиной, валидные принимаются; UI не «зависает».
- Диалог, не найденный в ЛК, может отклониться и позже — на этапе
  скачивания; тогда ошибка появится уже в таблице «Пачка» (строка
  «Ошибка», примечание «Не удалось скачать диалог из Twin24»). Оба
  места ошибки предусмотрены.

### 3.4. (г) Общая таблица «Пачка» и кнопка Excel

**Назначение.** Единая картина всех файлов обоих источников; здесь
живёт главный outcome — кнопка «Скачать результат (Excel)». Показывает,
что «две двери» ведут в одну комнату.

**Раскладка.** Полноширинная карточка. Шапка карточки: слева заголовок
«Пачка» и счётчики; под ними тонкая прогресс-полоса; справа — кнопка
Excel и её контекстные примечания. Тело — таблица:

```
┌ ПАЧКА · 12 из 50 файлов                    [Скачать результат (Excel)] ┐
│ Обработано 9 из 12 · ▓▓▓▓▓▓▓▓▓░░░                                          │
│ Дождитесь окончания обработки всех файлов — Excel собирается из всей пачки. │
│ ───────────────────────────────────────────────────────────────────────── │
│ Диалог            │ Источник │ Статус             │ Примечание           │
│ zvonok_0901       │ С диска  │ ↻ Транскрибируется │ —                    │
│ 01a0b657-6b6b-…   │ Twin24   │ ↻ Размечаются роли│ —                    │
│ zvonok_0903       │ С диска  │ ✓ Готово           │ —                    │
│ 09c3…-e2f1        │ Twin24   │ ✕ Ошибка           │ Не удалось скачать   │
│                   │          │                    │ диалог из Twin24     │
└─────────────────────────────────────────────────────────────────────────────┘
```

**Колонки.**
- **«Диалог»** — тот же ID, что попадёт в колонку «ID диалога» Excel:
  имя файла **без расширения** (для файлов с диска) или UUID (для
  Twin24). Длинные UUID усекаются многоточием, полное значение — в
  tooltip.
- **«Источник»** — pill-чип «С диска» / «Twin24» (мелкая иконка + текст;
  на узких экранах — только иконка с `aria-label`). Источники не
  группируются и не сортируются — пачка едина.
- **«Статус»** — pill-чип с мягким фоном (паттерн `.badge` MVP):
  «В очереди» (серый), «Транскрибируется» (акцент + спиннер),
  «Размечаются роли» (акцент + спиннер), «Готово» (зелёный), «Ошибка»
  (красный). Цвет никогда не единственный носитель смысла — всегда
  текст.
- **«Примечание»** — причина ошибки красным для строк «Ошибка», «—»
  для остальных. Примеры: «Не удалось скачать диалог из Twin24»,
  «Сбой распознавания — попробуйте добавить файл ещё раз» (текст
  уточняется по фактическим ошибкам backend).

**Счётчики и прогресс.** «12 из 50 файлов» (лимит виден заранее, без
 surprise-блокировок) + «Обработано 9 из 12» + тонкая полоса
(терминальные/все, 4–6 px, цвет акцента; полностью зелёная, когда всё
готово). Пока есть нетерминальные файлы, рядом muted-строка «Статусы
обновляются автоматически».

**Кнопка «Скачать результат (Excel)» — три состояния:**

| Состояние пачки | Кнопка | Сопровождение |
|---|---|---|
| Пустая | не отображается | заглушка `.empty` |
| Есть нетерминальные файлы | видима, **неактивна** (opacity, not-allowed) | muted-строка под кнопкой: «Обработано 9 из 12 — Excel собирается из всей пачки целиком» |
| `all_terminal` (успех или ошибка) | **активна** (primary) | если есть ошибки: «В Excel войдут все 12 записей; у 2 ошибочных вместо текста — причина ошибки» |

Решение «видима, но неактивна» вместо «появляется в конце»: правило
результата видно с самого начала (пользователь сразу понимает, что
Excel — на всю пачку), нет скачка макета и «кнопки из ниоткуда», а
счётчик превращает ожидание в видимый прогресс. Активация происходит
автоматически при поллинге — с мягким тостом «Обработка завершена —
можно скачать Excel».

**Повторная выдача и очистка WAV.** После первого успешного скачивания:
тост «Excel сформирован» и постоянное muted-примечание у кнопки:
«Исходные WAV удалены после первой выдачи. Excel можно скачать
повторно, пока живёт рабочий стол (24 ч).» Кнопка остаётся активной —
повторное скачивание работает (тексты живут до TTL).

**Живое обновление.** Поллинг `GET /api/state` каждые 3 с, пока есть
нетерминальные файлы (после `all_terminal` — останавливается,
возобновляется при добавлении новых). Чипы, счётчики, полоса и
состояние кнопки пересчитываются без перезагрузки. Спиннеры внутри
активных чипов показывают, что процесс идёт, а не «завис».

**Догрузка в ту же пачку.** Обе панели ввода остаются активными всегда
(смешивание режимов разрешено). Новые строки добавляются в конец
таблицы; кнопка Excel возвращается в «неактивна», счётчики растут.
Формат Excel фиксирован: колонки «ID диалога» и «Текст транскрибации»
(«Оператор: … / Клиент: …») — можно упомянуть в подсказке у кнопки,
чтобы пользователь знал, что получит.

**Согласованность.** Таблица на белой `.card`, рамки `--border`,
приглушённая шапка колонок — нейтральный паттерн списков testing.
Статус-чипы — pill-бейджи MVP. Кнопка — `.btn-primary` портала.
Сортировки и фильтры **не делаем**: ≤50 строк, порядок добавения
стабилен и совпадает с ментальной моделью «как я их добавлял».

**Edge cases.**
- **409 на экспорт** (гонка: файл добавлен между рендером и кликом):
  тост «Пачка изменилась — дождитесь обработки новых файлов», кнопка
  снова неактивна.
- 50 строк: таблица прокручивается внутри карточки, шапка колонок
  «липнет» (sticky) — заголовок и кнопка Excel всегда видны.
- Двойной клик по Excel: кнопка на ~1 с блокируется после клика —
  одна навигация на скачивание.
- Файл «залип» в активном статусе долго (скачивание из Twin24 входит
  в этап «Транскрибируется»): снимается копией в панели Б: «Скачивание
  диалога из Twin24 входит в этап „Транскрибируется“ и может занять
  время.»

### 3.5. (д) Пустые состояния, сеть, 503, ожидание, возврат, TTL

**Матрица «тип ошибки → место показа»** (единая логика обратной связи):

| Тип | Место | Вид |
|---|---|---|
| Ошибка поля (логин Twin24) | под полем/формой | красный текст, поле остаётся заполненным |
| Ошибка строки (валидация импорта) | сводка панели Б | цитата строки + причина |
| Ошибка файла (загрузка, лимиты) | пункт очереди панели А | красный текст + «Повторить» |
| Ошибка обработки файла | колонка «Примечание» | причина в строке таблицы |
| Транзиентный результат (готово, Excel) | тост (вниз справа) | авто-скрытие ~4 с, паттерн MVP |
| Проблема связи (поллинг) | баннер в карточке «Пачка» | инлайн, не блокирует ввод |

**Первичная загрузка.** Мутед-строка «Загружаем рабочий стол…» до
первого `/api/state`; при ошибке — тот же баннер связи (ниже).

**Нет связи с сервером / 503 SSO-шлюза (открытая вкладка).** Поллинг
упал (в т.ч. 503 — `testing` недоступен, шлюз проверяет каждый запрос):
в карточке «Пачка» появляется баннер: «Нет связи с сервером. Данные
сохранены — статусы обновятся, когда связь вернётся.» Поллинг
продолжает попытки; при восстановлении баннер исчезает, статусы
догоняются. Ввод при этом формально возможен, но любые действия
завершаются локальной ошибкой — поля не блокируем, ошибки показываем
на месте (панель А: пункт красный; панель Б: тост). **Отдельного in-app
экрана 503 не существует:** если пользователь перезагружает страницу во
 время недоступности шлюза, статику не отдаёт nginx — он видит его
стандартную страницу. Это принимается (прецедент correction-audio).

**Долгое ожидание пачки.** Пачка из 50 файлов может считаться долго.
Средства от тревоги «зависло»: спиннеры в активных чипах; счётчик
«Обработано X из Y» двигается; muted-строка «Статусы обновляются
автоматически»; подсказка про этап Twin24 (см. 3.4). Вкладку можно
закрыть и вернуться (ниже).

**Возврат в закрытую вкладку (восстановление по cookie).** Рабочий
стол восстанавливается из `transcribe_ws`: таблица отрисовывается из
`/api/state` с текущими статусами; если всё уже готово — кнопка Excel
сразу активна. Подключение Twin24 могло сброситься (рестарт
контейнера): панель Б показывает состояние «сброшено» с пояснением
«файлы и результаты не потеряны» (3.3). Две открытые вкладки с одной
cookie — один и тот же стол: обе поллят и сходятся к одному
состоянию, конфликтов нет.

**Очистка по TTL (24 ч без активности).** Возврат — к пустому столу;
нейтральная заглушка 3.1, без «данные удалены»-экрана (сервер не
сообщает факт очистки — см. §5.5). Ожидаемость обеспечивается вводной
строкой и карточкой портала.

**Edge cases.**
- Рестарт контейнера во время обработки: нетерминальные файлы
  потеряны (состояние pipeline не переживает рестарт) — при следующем
  поллинге таблица отражает фактическое состояние сервера; если сервер
  сообщает о потерянных строках, они показываются как «Ошибка:
  обработка прервана — добавьте файл заново» (уточнить с architect,
  см. §5.8).

### 3.6. (е) Коммуникация «данные живут ограниченное время»

Принцип: честно, спокойно, заблаговременно, без модальных окон.
Формулировки — факт, а не предупреждение (прецедент — карточка
корректора на портале: «Данные не сохраняются: живут только во время
визита»). Три места:

1. **Вводная строка под шапкой** (видно до первого действия):
   «Результат — один Excel на всю пачку. Тексты храним 24 часа с
   момента последней активности; после первого скачивания Excel
   исходные аудио удаляем — сам Excel можно скачать повторно.»
2. **Примечание у кнопки Excel после первой выдачи** (момент, когда
   пользователь принял результат): «Исходные WAV удалены после первой
   выдачи. Excel доступен для повторного скачивания, пока живёт
   рабочий стол (24 ч).» Если `/api/state` начнёт отдавать остаток TTL
   (см. §5.5) — уточнять: «…ещё 19 ч».
3. **Карточка подсистемы на портале** (вне этой страницы; дополнение к
   `portal-ui.md` §4, формат его карточек):

   - **Иконка:** один inline-SVG глиф «волна сигнала» (viewBox 24,
     stroke currentColor, stroke-width 2) — для карточки портала и
     шапки подсистемы, единообразно с существующими.
   - **Заголовок:** `Транскрибация звонков`
   - **Описание (3 предложения, с честной оговоркой о хранении):**
     > «Записи звонков — в текст с ролями оператор и клиент. Добавьте
     > WAV-файлы или импортируйте диалоги из ЛК Twin24 и скачайте один
     > Excel. Данные храним ограниченное время: тексты — 24 часа,
     > исходные аудио удаляются после выдачи результата.»
   - **Действие:** `Открыть →`; **ссылка:**
     `https://transcribe.bot-atelier.ru/`. Порядок в сетке портала:
     в конец (после correction-audio), по правилу portal-ui.md §4.3.

### 3.7. (ж) Ключевая UI-копия (русский)

Тональность — как у портала и testing: коротко, по делу, без
канцелярита и без восклицательных знаков. Числа лимитов в копии —
параметры (меняются в одном месте при подтверждении §5.1).

**Шапка и вводные:**

## 4. Рекомендация по дизайн-языку

**Рекомендация: гибрид «шапка MVP + тело экосистемы».**

- **Шапка — тёмная, паттерн MVP acoustic-matcher (#13213a, белый
  заголовок + muted-подзаголовок, тихая кнопка-анкер «← На главную»
  тёмно-синяя #1b2c4a).** Обоснование: тёмная шапка — визуальная
  сигнатура «самостоятельной подсистемы» экосистемы; transcribe —
  sibling подсистемы correction-audio (та же модель: отдельный
  поддомен, статическая страница без сборки, SSO-шлюз, эфемерный
  рабочий стол), и совпадающая «рамка» мгновенно считывается как «это
  один класс инструментов». MVP уже доказал, что тёмная шапка
  сочетается со светлым телом.
- **Анкер «← На главную» — крайний левый элемент шапки**, по целевой
  конвенции `portal-ui.md` §5.1 («единый экосистемный левый угол»),
  тихой вторичной кнопкой — не primary и не рядом с «опасными»
  действиями. В живом MVP корректора анкер справа — это «до»-состояние
  из того же документа (§5.3, схема «После» — слева). Новая подсистема
  реализует целевое состояние, а не закрепляет устаревшее; при
  следующем обновлении correction-audio все три шапки сойдутся.
- **Тело — светлый язык портала/testing, токен в токен:** фон
  `--bg #f3f4f6`, карточки `--surface #fff` с рамкой `#e5e7eb` и тенью
  при hover, текст `#1f2937`/`#111827`, muted `#6b7280`, акцент
  `#3498db` (кнопки primary, активные чипы, drag-over), радиус 10 px
  (кнопки 6 px), `system-ui`, кнопки `.btn / .btn-primary /
  .btn-secondary`, иконки — только inline SVG (viewBox 24, stroke
  currentColor, stroke-width 2), без эмодзи, focus-ring
  `0 0 0 3px rgba(52,152,219,.15)`, пустые состояния `.empty`.
  Обоснование: (1) требование portal-ui.md «выглядеть как обложка той
  же системы» распространяется на весь путь пользователя — с карточки
  портала он попадает на страницу того же визуального мира; (2)
  смысловой центр transcribe — **таблица данных со статусами**, а не
  мастер из трёх шагов: светлый язык testing/портала для таблиц
  читается лучше; (3) язык уже описан переменными и переносится в
  inline-CSS без сборки без каких-либо затрат.
- **От MVP берём структурные паттерны, не стилистические:** toast-зона
  внизу справа (тёмный тост, красный вариант для ошибок, авто-скрытие
  ~4 с), pill-бейджи статусов с мягким фоном, первый рендер из
  `/api/state`. Шаги-карточки radius 16, Inter и акцент #1769e0 **не**
  переносим: у transcribe другой жанр страницы.
- **Статусные цвета** (в дополнение к палитре, в её плоской гамме):
  готово — зелёный #27ae60 на `rgba(39,174,96,.12)`; ошибка — #e74c3c
  на `rgba(231,76,60,.12)`; в полёте — акцент #3498db на
  `--accent-soft`; в очереди — `#6b7280` на `#f3f4f6`. При
  реализации сверить с фактическими статусными цветами `testing`
  (см. §5.9).
- **Итог:** не изобретается ни одного нового визуального паттерна:
  рамка — от подсистемы-прецедента, содержание — от экосистемы.
  Пользователь с портала не чувствует смены дизайн-системы, а
  постоянный пользователь correction-audio узнаёт знакомый «проводник».

## 5. Открытые UX-вопросы

1. **Лимиты (25 МБ / 50 файлов / 1 ГБ).** Предложение architect ждёт
   подтверждения пользователя. Копия подсказок завязана на числа; в
   реализации вынести их в один конфиг/константу.
2. **Формат ввода Twin24: построчно vs разделители.**    Рекомендую
   построчно (как architect): единственное правило, ноль неоднозначностей,
   placeholder обучает формату. Смягчения: молча игнорировать
   пустые строки и хвостовые пробелы.
3. **Скачивание результата по одному файлу до завершения пачки.**
   Рекомендую **не делать в v1**: единый артефакт проще понимается,
   кнопка с честным счётчиком уже снимает тревогу ожидания; частичные
   ошибки не блокируют целую пачку. Вернуться к вопросу, если пачки
   регулярно длятся >15–20 минут; потребует решений architect (считать
   ли частичную выдачу «первой выдачей» для очистки WAV; новый
   эндпоинт).
4. **Показ email подключённой ЛК Twin24.** Рекомендую показывать
   (подтверждает, чей кабинет подключён; полезно рядом с «Сменить
   учётную запись»), если backend держит email в RAM. Если нет —
   показывать просто «ЛК Twin24 подключён».
5. **Дополнительные поля `/api/state`:** `expires_at` (остаток TTL) и
   занятый объём (для «X из 1 ГБ»). Позволяют заменить качественные
   «24 часа» на точные «ещё 19 ч» у кнопки Excel. Вопрос к architect.
6. **«Начать новую пачку» / очистка стола после выдачи Excel.** Лимит
   50 файлов + TTL 24 ч могут «законсервировать» полный стол без
   возможности добавить новое. Нужен ли явный сброс (кнопка в шапке
   карточки «Пачка» + API-метод) — вопрос к architect; UI-место
   зарезервировано.
7. **Удаление файла из очереди до начала обработки.** API не
   предусматривает; сейчас ошибочно добавленный файл дожидается конца
   пачки. Стоит ли добавить (кнопка «Убрать» в строке со статусом
   «В очереди») — вопрос к architect.
8. **Потеря нетерминальных файлов при рестарте контейнера.** Как
   сервер сообщает об этом в `/api/state` (строки исчезают? помечаются
   ошибкой?) — влияет на копию строки «Обработка прервана — добавьте
   файл заново». Вопрос к architect.
9. **Свёрка статусных цветов с `testing`.** Предложенные #27ae60/#e74c3c
   — из плоской гаммы портала; при реализации сверить с фактическими
   цветами статусов `testing` и при расхождении взять его.
10. **Иконка подсистемы.** Предложена «волна сигнала» (inline SVG);
    метафора на утверждении по аналогии с portal-ui.md §9.3.
