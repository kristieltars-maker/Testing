# UX/UI-дизайн модуля «Корректор аудио-файлов»

## 1. Вход в подсистему и навигация

### 1.1. Область применения пункта меню

Модуль `audio-correction` привязан к проекту (как и `testing`). Пункт меню **не добавляется в глобальную верхнюю панель**, а показывается внутри проектного контекста. Это повторяет существующую модель: в приложении нет боковой панели, навигация по проекту идёт через заголовок проекта и вторичные ссылки.

### 1.2. Проектная навигация — горизонтальные вкладки

На всех страницах проекта (замечания, корректор аудио, управление) под шапкой страницы добавляется строка вкладок:

```
┌─────────────────────────────────────────────────────────────────────┐
│ ← Проекты                                                           │
│ Название проекта                       [Закрыть / Забыть]           │
│                                                                     │
│ [ Замечания ] [ Корректор аудио-файлов ] [ Управление ]             │
└─────────────────────────────────────────────────────────────────────┘
```

- **Активная вкладка**: текст `#3498db`, нижняя граница 2 px того же цвета, начертание 600.
- **Неактивная вкладка**: цвет `#6b7280`, без границы; при наведении фон `#f3f4f6`.
- Вкладка «Управление проектом» видна только админу/руководителю проекта (как сейчас).
- На мобильных экранах вкладки переносятся на новую строку или сворачиваются в раскрывающийся список.

### 1.3. Точки входа

1. **Из списка проектов** (`/`): карточка проекта не перегружается дополнительными кнопками. Вход осуществляется через страницу проекта.
2. **Из страницы замечаний проекта** (`/projects/:projectId`): пользователь видит вкладку «Корректор аудио-файлов» и переключается на неё.
3. **Из URL напрямую**: `/projects/:projectId/audio-correction`.

### 1.4. Согласование с существующей экосистемой

- Используется тот же контейнер `.page` (max-width 1100 px, padding 24/20/60).
- Шапка `.page-header` с заголовком проекта и основным действием повторяет страницу IssuesPage.
- Карточки `.card`, бейджи `.badge`, пустые состояния `.empty`, кнопки из `index.css` берутся без изменений.

## 2. Маршруты модуля

| Маршрут | Назначение |
|---|---|
| `/projects/:projectId/audio-correction` | Единый рабочий стол корректора аудио-файлов внутри проекта |

Подсистема имеет **только один маршрут**. Внутри него нет подстраниц: создание, настройка, обработка и результаты показываются как секции одной страницы.

## 3. Единый рабочий стол «Корректор аудио-файлов»

### 3.1. Назначение и роли

Экран используется любым участником проекта (`project_members`) для разового акустического выравнивания. Пользователь загружает эталонную запись, загружает одну или несколько целевых записей, настраивает параметры, запускает фоновую обработку, слушает и скачивает результаты, после чего закрывает подсистему — и все файлы и результаты удаляются.

**Права:**

- Любой член проекта может загружать файлы, запускать обработку, скачивать результаты и закрывать рабочий стол.
- Никаких ролевых ограничений внутри модуля нет.

### 3.3. Шапка страницы

- **Заголовок** — название проекта + клиент, как в IssuesPage.
- **Кнопка «Закрыть / Забыть»** — всегда видна в правой части шапки, оформлена как опасная вторичная кнопка (красный контур или красный текст).
  - При нажатии открывается модальное подтверждение.
  - После подтверждения отправляется `DELETE /session`, сессия и файлы удаляются, пользователя возвращает на страницу проекта `/projects/:projectId`.
- **Вкладки проекта** — активна «Корректор аудио-файлов».

### 3.4. Модальное подтверждение «Закрыть / Забыть»

```
┌──────────────────────────────────────────┐
│ Закрыть корректор и забыть данные?       │
│                                          │
│ Все загруженные файлы, результаты         │
│ обработки и отчёты будут безвозвратно    │
│ удалены. Это действие нельзя отменить.   │
│                                          │
│            [Отмена]  [Закрыть / Забыть]  │
└──────────────────────────────────────────┘
```

- Заголовок модалки: «Закрыть корректор и забыть данные?»
- Текст: «Все загруженные файлы, результаты обработки и отчёты будут безвозвратно удалены. Это действие нельзя отменить.»
- Кнопка подтверждения — красная, текст «Закрыть / Забыть».
- Пока идёт обработка, кнопка подтверждения заменяется на «Остановить и забыть»; sidecar-задача отменяется перед очисткой.

### 3.5. Защита от случайного ухода

- **При попытке закрыть вкладку/браузер** (`beforeunload`): показывается стандартное браузерное предупреждение «Если вы закроете вкладку, все загруженные файлы и результаты будут удалены. Оставить страницу?».
- **При попытке перейти внутри SPA** на другой маршрут (вкладка «Замечания», «Управление», возврат к проектам): показывается кастомное подтверждение с тем же текстом. Подтверждение отправляет `DELETE /session` и позволяет уйти; отмена оставляет пользователя на рабочем столе.
- **При открытии второй вкладки** с `/projects/:projectId/audio-correction`: фронтенд показывает предупреждение «Корректор уже открыт в другой вкладке. Открыть здесь и сбросить предыдущую сессию?». При согласии сервер генерирует/привязывает новый `session_id`, старая сессия помечается к удалению по TTL или остаётся висеть до своего TTL.

### 3.6. Секция «Эталонная запись»

- **Зона загрузки**: большая карточка с пунктирной рамкой, иконка звуковой волны, текст «Перетащите эталонный аудиофайл или нажмите для выбора».
- Допустим только **один файл**.
- После выбора отображается карточка файла: название, формат, размер, длительность (если удалось прочитать метаданные), кнопка удаления.
- Загрузка файла происходит сразу после выбора (session-scoped), без отдельной кнопки «Сохранить».
- Если файл не соответствует формату или превышает 50 МБ — под зоной появляется красная подсказка, файл не отправляется.

### 3.7. Секция «Целевые записи»

- **Зона загрузки**: аналогичная, но с текстом «Перетащите один или несколько целевых аудиофайлов».
- Поддерживается **множественная загрузка**.
- Список файлов под зоной: каждая строка — название, размер, индикатор валидации, кнопка удаления.
- При попытке загрузить файл неподдерживаемого формата строка помечается красным, рядом текст ошибки; остальные файлы остаются в списке.
- Загрузка каждого файла также session-scoped.

### 3.8. Секция «Настройки обработки»

#### 3.8.1. Макро-ручки

Две крупные ползунковые группы, понятные пользователю без знания алгоритма:

| Ручка | Диапазон | Влияние |
|---|---|---|
| **Дистанция микрофона** | `Близко` → `Средне` → `Далеко` | Меняет группу параметров, связанных с близким/удалённым звучанием (уровень прямого звука, компрессия, эквализация). |
| **Реверберб/эхо** | `Сухо` → `Средне` → `Реверберированно` | Меняет параметры пространственной обработки и подавления/добавления реверберации. |

- Ползунок отображается визуально как трек с тремя метками; текущее значение подписано справа.
- При движении ручки в группах параметров появляются маркеры «изменено макро».
- Кнопка **«Сбросить макро»** возвращает ручки в положение по умолчанию и сбрасывает связанные параметры.

#### 3.8.2. Рекомендации

- Карточка «Рекомендации Sidecar».
- Содержит список предложений, полученных на основе анализа эталона (например, «Увеличить компрессию», «Снизить высокие частоты»).
- Кнопка **«Применить рекомендации»** обновляет соответствующие ползунки/поля.
- Если рекомендаций нет, карточка скрыта или показывает «Автоматических рекомендаций нет».

#### 3.8.3. Продвинутые параметры

- Параметры алгоритма acoustic matching разбиты на **свертываемые группы**:
  1. Уровни и громкость
  2. Спектр и тембр
  3. Динамика
  4. Пространство / реверберация
  5. Лимитирование
  6. Прочее
- В каждой группе: поля ввода чисел и/или ползунки, метки с единицами измерения, подсказки (title) с пояснением.
- По умолчанию группы свёрнуты, кроме первой, чтобы не перегружать интерфейс.
- Подписи и диапазоны параметров берутся из конфигурации Python-sidecar (уточняется от владельца алгоритма).

### 3.9. Кнопка «Запустить обработку»

- Располагается под секцией настроек.
- **Доступна**: загружен эталон, есть хотя бы одна целевая запись, нет ошибок валидации файлов, текущий запуск не выполняется.
- **Недоступна**: не выполнены условия выше или идёт обработка. Текст меняется на «Запуск…».
- При повторном запуске предыдущий текущий run может быть перезаписан или заменён новым — история не сохраняется.

### 3.10. Общий прогресс обработки

- Показывается только после нажатия «Запустить обработку» и до завершения.
- **Линейный прогресс-бар** с процентом выполнения (расчёт на основе обработанных целевых записей / общего числа).
- Рядом спиннер и кнопка «Отменить».
- Обновление происходит через polling каждые 2 секунды (`GET /session/runs/:runId`).

### 3.11. Секция «Результаты текущего запуска»

Появляется после завершения обработки (статус `done`, `partial` или `failed`).

Каждая целевая запись отображается как отдельная карточка `.card`:

| Блок | Описание |
|---|---|
| **Название файла** | Исходное имя файла. |
| **Волновая форма** | Декоративная визуализация waveform (placeholder из вертикальных полосок разной высоты). Не заменяет `<audio>`. |
| **Плееры** | Два плеера: «Исходник» и «Исправленный». Если результата ещё нет, плеер результата disabled. |
| **Метрики** | Табличка или строка метрик: LUFS, True Peak, LRA, RT60 и др. (до/после). Для отсутствующих значений — «—». |
| **Действия** | «Скачать исправленный файл», «Скачать отчёт по записи». |
| **Статус цели** | Маленький бейдж: в очереди / обрабатывается / успешно / ошибка. |

Для эталона в верхней части секции также добавлен отдельный плеер «Эталон».

При нажатии play в одном плеере остальные не останавливаются автоматически (допустимо для сравнения); при необходимости добавляется кнопка «Solo — слушать только этот».

### 3.12. Скачивание результатов

- **По записи**: кнопка «Скачать исправленный файл» (формат совпадает с исходным или задан в настройках).
- **По сессии**: кнопка «Скачать все результаты (ZIP)» внизу секции результатов, доступная, если есть хотя бы один успешный результат.
- **Отчёт**: кнопка «Скачать полный отчёт» (JSON/PDF/HTML — формат определяется sidecar).

### 3.13. Состояния элементов в зависимости от этапа

| Элемент | Нет файлов | Файлы загружены | Обработка | Есть результаты |
|---|---|---|---|---|
| Кнопка «Запустить обработку» | disabled | enabled | «Запуск…» / disabled | enabled (перезапуск) |
| Секция настроек | доступна | доступна | заблокирована (read-only) | доступна |
| Список целевых файлов | пустое состояние | удаление доступно | удаление disabled | удаление доступно |
| Секция результатов | скрыта | скрыта | прогресс-бар | показана |
| Кнопка «Скачать ZIP» | скрыта | скрыта | скрыта | enabled, если есть успешные результаты |

### 3.14. Edge cases

- **Пустое состояние при входе**: секции эталона и целей показывают зоны drag-and-drop с иконкой и поясняющим текстом; секция результатов скрыта; кнопка «Запустить обработку» disabled.
- **Загрузка**: в списке файлов появляется строка с названием и спиннером; зона загрузки временно disabled.
- **Ошибка загрузки файла**: под списком файлов появляется красная плашка с текстом ошибки и кнопкой «Повторить».
- **Превышение 50 МБ**: файл отмечается, текст «Превышен максимальный размер 50 МБ».
- **Неподдерживаемый формат**: текст «Формат не поддерживается. Допустимы: WAV, FLAC, MP3, M4A, AAC, OGG, Opus».
- **Обработка не запускалась**: карточки целей не отображаются, секция результатов скрыта.
- **Ошибка обработки**: красная плашка с сообщением из sidecar; кнопка «Повторить запуск».
- **Частичный успех**: общий статус `done`, но отдельные цели помечены как failed; успешные результаты доступны для скачивания.
- **Отмена пользователем**: обработка останавливается, результаты появляются только для успевших обработаться целей.
- **Polling-ошибка**: в правом верхнем углу неблокирующий тост «Не удалось обновить статус» с кнопкой «Повторить».
- **Сессия утеряна / истекла**: вместо рабочего стола показывается пустое состояние `.empty` с текстом «Сессия устарела или была закрыта в другой вкладке. Все файлы и результаты удалены.» и кнопкой «Обновить страницу» (перезагрузка создаёт новую сессию).
- **Нет результатов для скачивания**: кнопка ZIP disabled с подсказкой при наведении.

## 4. Жизненный цикл рабочего стола

```
Открыть подсистему
        ↓
Загрузить эталон (1 файл)
        ↓
Загрузить целевые записи (1..N файлов)
        ↓
Настроить параметры / применить рекомендации
        ↓
Нажать «Запустить обработку»
        ↓
Polling статуса run (progress-bar inline)
        ↓
Результаты появляются в секции ниже
        ↓
Прослушать / скачать файлы и отчёты
        ↓
Нажать «Закрыть / Забыть» → подтверждение → DELETE /session → cleanup
```

- Пользователь может перезапустить обработку с теми же файлами и новыми настройками без создания отдельной задачи. Предыдущий run заменяется текущим в сессионном хранилище; старые выходные файлы удаляются при старте нового run.
- При уходе со страницы (явном или через guards) сессия уничтожается; при повторном входе начинается новый жизненный цикл.

## 5. Ключевые интеракции

### 5.1. Загрузка файлов

1. Пользователь перетаскивает файл в зону эталона или целей.
2. Файл появляется в списке с индикатором проверки.
3. Клиентская валидация проверяет формат и размер **до отправки**.
4. При успешной валидации файл отправляется на сервер в сессионную директорию.
5. Во время загрузки показывается спиннер или прогресс (опционально).
6. После успешной загрузки кнопка «Запустить обработку» активируется.

### 5.2. Запуск обработки

1. Пользователь нажимает «Запустить обработку».
2. Кнопка меняется на «Запуск…», появляется прогресс-бар.
3. Фронтенд начинает polling `/session/runs/:runId`.
4. Обновляются общий прогресс-бар и статусы отдельных целей.
5. По завершении статус меняется на `done`/`failed`/`partial`; результаты и метрики отрисовываются автоматически.
6. Пользователь может в любой момент нажать «Отменить».

### 5.3. Прослушивание и сравнение

1. Пользователь нажимает play у исходника или результата.
2. Аудио воспроизводится через нативный плеер.
3. Метрики до/после расположены рядом с соответствующим плеером для удобного сравнения.

### 5.4. Скачивание

1. Индивидуальные файлы скачиваются по прямым ссылкам `/uploads/...` внутри сессионной директории.
2. ZIP-архив формируется бэкендом по запросу из текущих выходных файлов сессии; во время подготовки кнопка показывает спиннер.
3. Полный отчёт скачивается аналогично из текущего run.

### 5.5. Закрытие и очистка

1. Пользователь нажимает «Закрыть / Забыть».
2. Показывается модальное подтверждение.
3. При подтверждении отправляется `DELETE /session`.
4. Сессионная директория и файлы удаляются на сервере.
5. Пользователя перенаправляет на `/projects/:projectId`.
6. Если sidecar-задача выполнялась, она отменяется перед удалением.

## 6. Мобильная / адаптивная версия

- **< 1024 px**: двухколоночный макет настроек превращается в одноколоночный; настройки обработки идут под загрузкой файлов.
- **< 768 px**:
  - Вкладки проекта сворачиваются в раскрывающийся селект или переносятся.
  - Волновые формы скрываются, остаются только плееры и метрики.
  - Кнопки действий располагаются вертикально друг под другом.
  - Кнопка «Закрыть / Забыть» занимает всю ширину под заголовком.
- **Touch**: ползунки настроек увеличиваются по высоте для удобного захвата пальцем.

## 7. Принципы дизайна

1. **Один экран — один цикл**. Вся работа происходит на одном рабочем столе без переходов между списком, созданием и деталями. Пользователь всегда понимает, на каком этапе находится сессия.
2. **Эфемерность как явный контракт**. Кнопка «Закрыть / Забыть» и предупреждения при уходе делают политику хранения прозрачной: данные живут только здесь и сейчас.
3. **Карточная структура**. Каждая целевая запись, каждая группа параметров и каждый блок загрузки оформлены карточками `.card`, что визуально отделяет сущности друг от друга и повторяет стиль IssuesPage.
4. **Макро-ручки + продвинутые параметры**. Пользователь без аудио-опыта может ограничиться двумя ползунками, а опытный — раскрыть детальные параметры. Рекомендации sidecar помогают принять решение.
5. **Визуальный feedback**. Цветные бейджи статусов, прогресс-бар, спиннеры, waveform-placeholder и плееры дают понятную обратную связь о текущем состоянии обработки.
6. **Переиспользование паттернов**. Используются существующие `.page-header`, `.card`, `.badge`, `.empty`, цвета кнопок и типографика, чтобы модуль выглядел как органичная часть приложения, а не отдельный продукт.
7. **Безопасность действий**. Закрытие сессии требует подтверждения; уход со страницы блокируется предупреждением; недоступные действия явно disabled с пояснением.
8. **Обработка ошибок на каждом шаге**. Валидация файлов, ошибки sidecar, сетевые сбои polling, утеря сессии — всё отображается inline без блокировки интерфейса.
